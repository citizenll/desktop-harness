# DSH 上游同步与内置市场边界

## 目标

DSH Desktop 必须能够持续升级 DeepSeek Harness，同时保留桌面端产品能力。升级的衡量标准不是“没有补丁”，而是：上游版本整列一致、下游差异可审计和重放、旧用户数据可原地升级、发行产物可验证和回滚。

插件市场是 DSH Desktop 的内置能力，不属于 DSH 上游同步链。Desktop 只复用公开的商店目录数据，并自行维护市场代码、安装流程和界面集成。

## 架构边界

### DSH 上游层

- 所有 `@deepseek-ai/dsh-*` 包必须来自同一个发行版本。
- 依赖必须使用精确版本；不得通过 `latest`、宽范围或独立 Dependabot PR 升级单个 DSH 包。
- 上游升级以单独的 `chore/dsh-<version>` 分支和 PR 完成，不混入无关功能。
- Desktop 对 DSH 的必要修改保存在 `patches/`，并由 `patches/manifest.json` 记录意图、测试和移除条件。

### Desktop 产品层

- `packages/dsh-desktop-plugin-runtime` 提供固定 Profile、打包后的 pnpm 执行边界和插件操作服务。
- `packages/dsh-desktop-market` 提供内置市场服务与客户端，不从 npm 安装 `dshmarket`，也不跟随其上游版本。
- 市场允许复用商店目录的数据协议和端点，但任何上游代码更新必须经过代码审查、测试和显式移植。
- DSH 相关适配集中在市场入口和 Desktop runtime；市场目录、筛选和业务逻辑不得直接依赖 DSH 私有服务。

## 不变量

1. 不使用 `--force`、`--legacy-peer-deps` 或忽略脚本来掩盖正式安装问题。
2. `npm ci` 必须能在全新目录使用默认 peer resolver 完成。
3. 市场不能更新、卸载或重新安装自身。
4. 旧 Profile 中用户安装的 `dshmarket` 可以被迁移清理，但不得删除其他插件、市场状态、会话或模型配置。
5. `app.asar` 只包含运行时文件；市场源码、补丁、lockfile 和构建工具不得进入安装包。
6. 所有保留补丁必须有行为测试；仅检查补丁文本不能作为唯一回归保护。
7. 配置迁移必须幂等；重复启动不得重复修改或损坏用户数据。

## DSH 升级流程

1. 记录目标 DSH tag、commit、发布日期和直接依赖版本。
2. 更新所有直接 `@deepseek-ai/dsh-*` 精确版本并生成 lockfile。
3. 运行 release-train 检查，拒绝混用不同 DSH 版本。
4. 对照上游源码逐项审核补丁：删除已被上游实现的补丁、重放仍需要的补丁、重写发生契约变化的补丁。
5. 执行单元测试、类型检查、真实 Harness 启动和运行时 staging 验证。
6. 使用上一正式版用户数据副本执行原地升级验证。
7. 构建 Windows、macOS ARM64/x64、Linux 安装包；先发布预览版，再发布正式版。

## 补丁治理

`patches/manifest.json` 是补丁队列的事实来源。每项至少包含：

- 补丁文件和目标包版本；
- Desktop 需要该修改的原因；
- 对应的行为测试；
- 上游是否已有 Issue、PR 或替代能力；
- 可删除补丁的明确条件。

补丁按以下顺序处理：

1. 上游已实现：删除补丁并保留兼容行为测试。
2. 可通过 Cordis slot 或 Desktop adapter 实现：迁移出 DSH 包。
3. 必须修改上游内部实现：重新生成 patch-package 补丁并保留最小 diff。

## 内置市场维护

- 内置包保留 `/dsh-market/*` 路由和现有客户端模块标识，避免破坏浏览器端与旧数据迁移。
- 商店目录不可用时优先使用随包快照或最近一次有效缓存，并向用户显示明确状态。
- 插件安装、卸载和更新统一通过 `desktopPnpm`，不得直接寻找系统 pnpm。
- 市场自身不出现在可安装、更新、卸载和插件分组列表中。
- 从 dsh-market 上游吸收代码时记录来源 commit 和涉及文件，不进行整包自动同步。

## 验收矩阵

每次 DSH 升级至少验证：

- 全新安装与旧版本覆盖安装；
- 首次模型配置、Provider 错误分类和模型切换；
- 图片粘贴、上传、持久化与视觉模型请求；
- Preset 导入导出、插件配置、插件列表和内置市场；
- 插件安装失败恢复、重复插件恢复和 pnpm 环境修复；
- 手机局域网访问、临时公网通道和设置 Panel；
- Windows 标题栏、品牌资源、更新检查和退出流程；
- `npm test`、`npm run typecheck`、`npm run package:dir`；
- GitHub Actions 的 Windows、macOS ARM64/x64 与 Linux 构建。

## 发布与回滚

- DSH 上游升级对应一个 Desktop 预发布版本，例如 `v0.1.2-rc.1`。
- 预发布必须经过真实安装、旧数据升级和关键功能人工冒烟测试。
- 数据迁移保持向后兼容；若无法兼容，必须先创建可恢复备份并版本化迁移。
- 上一正式版安装包保持可下载，出现阻断问题时停止自动推广并回滚应用版本。
